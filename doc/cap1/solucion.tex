\section{Generación sintética de imágenes}

Los sistemas de extremo a extremo tiene la desventaja de requerir grandes cantidades de datos
para conseguir resultados con bajo error de entrenamiento y generalización;
habitualmente en el rango de 10 mil - 50 mil fotografías. 
En el tiempo disponible para la ejecución del proyecto no es posible 
capturar y etiquetar tal cantidad, además el costo de etiqueta de datos es 
elevado. El problema se mitiga utilizando imágenes sintéticas;
incrementando el conjunto de datos disponibles. 
Tales imágenes son creadas con base a la caracterización de las placas reales
y la fuente tipográfica usada en las mismas.

El conjunto artificial es utilizado para entrenar el modelo,
mientras que el conjunto de placas auténticas es usado
para la evaluación del sistema. Con ello se puede evaluar, indirectamente,
la utilidad de la estrategia, y la representatividad con la que conjunto sintético
asemeja al conjunto real en sus características esenciales.

En Costa Rica a las placas vehiculares se les asigna un código según el tipo de vehículos.
El reglamento sobre placas vehiculares especifica los códigos existentes, así como el color
del fondo de la placa y el color de los caracteres \cite{art97placasvehiculares}. Hay
más de 100 tipos de placas distintas.
Automóviles con códigos atípicos como el de placas extranjeras son poco probables de ser evaluadas;
además en el conjunto de imágenes reales no hay muestras de todos los tipos de placas.
Por este motivo solo se sintetizan placas basadas en las existentes en el conjunto de datos real
y las demás se dejan como casos no cubiertos o casos extremos. Los casos a cubrir se
muestran en la tabla \ref{tab:combinaciones-placas},

Durante el entrenamiento del modelo de reconocimiento de placas, se aplican
técnicas de aumento de datos (data augmentation) para incrementar la variabilidad
de las imágenes y mejorar la capacidad de generalización del modelo. El tipo de
aumento y la intensidad deben ser cuidadosamente seleccionados para evitar
introducir artefactos que puedan confundir al modelo. Por lo tanto, se seleccionan
posibles transformaciones y intensidades basadas en las características del conjunto de datos real,
y luego durante el entrenamiento se realizan experimentos para determinar cuáles combinaciones
producen mejores resultados. Entre las técnicas de aumento de datos utilizadas se incluyen:

\begin{itemize}
	\item Rotación: Se aplican rotaciones aleatorias dentro de un rango de -30 a 30 grados.
	\item Escalado: Se aplican escalados aleatorios dentro de un rango de 70\% a 120\%.
	\item Cambio de brillo y contraste: Se ajustan aleatoriamente el brillo y el contraste
		dentro de un rango de -20\% a +20\%.
	\item Perspectiva: Se aplican transformaciones de perspectiva aleatorias
		para simular diferentes ángulos de captura.
	\item Ruido: Se añade ruido gaussiano con una desviación estándar aleatoria entre 0 y 0.05.
	\item Desenfoque: Se aplica desenfoque gaussiano con un radio aleatorio entre 0 y 1.5 píxeles.
	\item Pixelado: Se aplica pixelado con un tamaño de bloque aleatorio entre 1 y 5 píxeles.
	\item Desplazamiento RGB: Se desplazan aleatoriamente los canales de color
		(R, G, B) dentro de un rango de -10 a +10 unidades.
	\item Compresión JPEG: Se simula compresión JPEG con una calidad aleatoria entre 55\% y 90\%.
	\item Aumentado por elemento: Se realiza aumentado de datos individuales por elemento de la placa:
		caracteres, plantilla, e imagen completa.
\end{itemize}

Puesto que se puede aplicar aumentado de datos en distintos elementos de la placa, 
en la rutina de generación de una única placa se especifican puntos de control 
para decidir de forma aleatoria que aumento aplicar en cada caso \ref{fig:diagrama-flujo-generador-placas}.

\section{Detección y extracción de ubicación de la placa en video e imágenes}

a modelos existentes. Se utiliza YOLOv11n, pues de las versiones de YOLO, la versión 11 ofrece
un buen balance entre precisión y velocidad, es adecuada para aplicaciones en tiempo real,

\section{Reconocimiento de número de placa}

La etapa de reconocimiento de números de placas se realiza también mediante ajuste fino 
a modelos existentes. De entre distintas versiones de modelos y arquitecturas se 
decide por utilizar \textbf{fast-plate-ocr}. Los modelos que ofrece son ligeros y rápidos;
además de que el entrenamiento y resulta bastante simple de realizar. Incluso 
es posible entrenar el modelo desde cero. 
Por otro lado, este proyecto es reciente y se encuentra constantemente en actualización.
A diferencia de otras arquitecturas como LPRNet, la cual es de hace 6 años aproximadamente
y es complejo o incluso imposible de ejecutar con las nuevas versiones de bibliotecas 
disponibles \cite{zherzdev2018lprnetlicenseplaterecognition}.
CLPRNet permite realizar el entrenamiento y el reconocimiento de
placa en una red extremo a extremo completa; sin embargo, este requiere un etiquetado de datos
de entrenamiento y validación mucho más completo, incluyendo parámetros como los vértices
en los que se ubica la placa y un número indicativo del tipo de placa (las variantes
de placas existentes) \cite{clprnet-paper}. Usar esta red implica, por lo tanto, reetiquetar los datos disponibles
y cambiar la estrategia de generación sintética de imágenes.
Finalmente, se consideró la opción de utilizar PaddleOCR; sin embargo, al igual
que LPRNet, esta red se encuentra desactualizada y poder ejecutarla con los nuevos paquetes
de PyTorch y GPU de NVIDIA no es sencillo e incluso imposible.

Fast plate OCR cuenta con dos modelos pre entrenados. En pruebas de concepto inicial
el modelo más pequeño (XS) resultó en un mejor compromiso entre precisión y velocidad de procesamiento,
por lo que se escoge el modelo base para realizar los experimentos.

\section{Integración de la solución}

Luego de determinar el mejor modelo de detección de placas,
y el mejor modelo de reconocimiento de placas se integran los modelos en una única solución.
Esta solución es capaz de procesar imagen y video (ya sea mediante cámara o pre grabado). 
Una vez obtenida la imagen se extraen dos puntos (Xmin, Ymin) y (Xmax, Ymax),
que se usan para definir la región donde se recorta la imagen. 
Esta imagen recortada se suministra el modelo de reconocimiento de placas, con 
lo cual se extrae confidencia y el texto reconocido. 
Se filtran las imágenes con baja confidencia. 
Finalmente, se dibuja la región de recorte en la imagen original
y el texto encima de la región de recorte \ref{fig:integracion-app}.
Este simple diseño es principalmente un prototipado para evaluar el correcto 
funcionamiento y viabilidad del sistema propuesto.
