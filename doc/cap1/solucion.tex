\section{Generación sintética de imágenes}

Los sistemas de extremo a extremo tienen la desventaja de requerir grandes cantidades de datos
para conseguir resultados con bajo error de entrenamiento y generalización;
habitualmente en el rango de 10 mil - 50 mil fotografías. 
En el tiempo disponible para la ejecución del proyecto no es posible 
capturar y etiquetar tal cantidad de imágenes, además el costo de etiquetar los datos es 
elevado. El problema se mitiga utilizando imágenes sintéticas;
incrementando el conjunto de datos disponibles. 
Tales imágenes son creadas con base a la caracterización de las placas reales
y la fuente tipográfica usada en las mismas.

El conjunto artificial es utilizado para entrenar el modelo,
mientras que el conjunto de placas auténticas es usado
para la evaluación del sistema. Con ello se puede evaluar, indirectamente,
la utilidad de la estrategia, y la representatividad con la que conjunto sintético
asemeja al conjunto real en sus características esenciales.

En Costa Rica a las placas vehiculares se les asigna un código según el tipo de vehículos.
El reglamento sobre placas vehiculares~\cite{art97placasvehiculares}
especifica los códigos existentes, así como el color del fondo de la placa y el color de los caracteres.
Hay más de 100 tipos de placas.
Automóviles con códigos atípicos, como el de placas extranjeras, son poco probables de ser evaluadas;
además, en el conjunto de imágenes reales no hay muestras de todos los tipos de placas.
Por este motivo solo se sintetizan placas basadas en las existentes en el conjunto de datos real
y las demás se dejan como casos no cubiertos o casos extremos. Los casos a cubrir se
muestran en la tabla~\ref{tab:combinaciones-placas},
y sus características en la tabla~\ref{tab:caracteristicas-placas}.

Se generan los datos utilizando plantillas de placas reales y la fuente tipográfica real,
realizando recortes de los caracteres y dejando plantillas lo más limpias posibles.
Un programa diseñado para este propósito crea placas aleatorias de forma sistemática,
utilizando el proceso mostrado en la figura~\ref{fig:diagrama-flujo-generacion-multiples-placas}.

Durante el entrenamiento del modelo de reconocimiento de placas, se aplican
técnicas de aumento de datos (data augmentation) para incrementar la variabilidad
de las imágenes y mejorar la capacidad de generalización del modelo. El tipo de
aumento y la intensidad deben ser cuidadosamente seleccionados para evitar
introducir artefactos que puedan confundir al modelo. Por lo tanto, se seleccionan
posibles transformaciones e intensidades basadas en las características del conjunto de datos real,
y luego durante el entrenamiento se realizan experimentos para determinar cuáles combinaciones
producen mejores resultados. Entre las técnicas de aumento de datos utilizadas se incluyen:

\begin{itemize}
	\item \textbf{Rotación (imagen):} Se aplican rotaciones aleatorias en el rango de $\pm20^{\circ}$ 
	      para simular inclinaciones de cámara o variaciones en el montaje de la placa.
	\item \textbf{Escalado (imagen):} Se aplican escalados aleatorios con un factor de $0.5$ a $1.0$ 
	      para representar cambios de distancia o zoom.
	\item \textbf{Transformación de perspectiva (imagen):} Se aplican transformaciones de perspectiva
	      con una desviación $\sigma$ entre $10$ y $60$, y desplazamientos relativos $dx,dy \in [0.1,\,0.6]$
	      para simular distintos ángulos de captura.
	\item \textbf{Cambio de brillo y contraste (imagen):} Se varía el brillo y el contraste 
	      mediante factores en el rango $[0.7,\,1.3]$, reproduciendo condiciones de iluminación natural.
	\item \textbf{Ruido (imagen):} Se añade ruido gaussiano con media $0$ y varianza entre $0.001$ y $0.01$,
	      imitando ruido del sensor o compresión digital.
	\item \textbf{Desenfoque (imagen):} Se aplica desenfoque gaussiano o de movimiento con un radio de 
	      $0.5$ a $2$ píxeles para representar movimiento o fuera de foco.
	\item \textbf{Pixelado (imagen):} Se simula pérdida de resolución aplicando pixelado con una escala 
	      de reducción entre $0.6$ y $1.0$ del tamaño original.
	\item \textbf{Desplazamiento RGB (imagen):} Se aplican desplazamientos de canales de color con
	      límites de $\pm20$ unidades por canal ($R$, $G$, $B$), simulando aberraciones cromáticas.
	\item \textbf{Compresión JPEG (imagen):} Se simula degradación por compresión con calidades entre 
	      $35$ y $75$, reproduciendo artefactos comunes en imágenes de baja calidad.
	\item \textbf{Cambio de relación de aspecto (imagen):} Se modifica la relación de aspecto entre 
	      $0.5$ y $1.0$, generando distorsiones leves en ancho o alto.
	\item \textbf{Escala de grises parcial (imagen):} Se convierte la imagen a escala de grises con 
	      mezcla ponderada promedio, para aumentar la robustez ante pérdida de color.
	\item \textbf{Texturizado de caracteres (carácter):} Se aplica variación aleatoria del color base 
	      en un rango de $\pm20$ unidades por canal RGB, imitando pintura irregular o desgaste.
	\item \textbf{Degradado de caracteres (carácter):} Se aplica erosión y difuminado sobre bordes
	      con kernels de $2\times2$ píxeles y entre $0$ y $2$ iteraciones, 
	      simulando desgaste del relieve o suciedad.
	\item \textbf{Cambio de color por tipo (carácter):} Los caracteres se recolorean según su categoría
	      (azul, rojo o verde), manteniendo coherencia con los tipos de placa reales.
	\item \textbf{Adición de tornillos u objetos (imagen):} Se añaden elementos visuales externos
	      de tamaño relativo entre $5\%$ y $10\%$ del ancho de la placa, ubicados en posiciones aleatorias.
\end{itemize}

Puesto que se puede aplicar aumentado de datos en distintos elementos de la placa, 
en la rutina de generación de una única placa se especifican puntos de control 
para decidir de forma aleatoria qué aumento aplicar en cada caso (ver figura~\ref{fig:diagrama-flujo-generador-placas}).
Cabe destacar que la selección de la plantilla y el carácter es aleatorio, seleccionando 
un elemento cualquiera de un directorio que contiene diferentes representaciones de cada clase,
pero se conoce en cada momento la correspondencia de la imagen con su etiqueta de número de placa.

\section{Reconocimiento de número de placa}
La etapa de reconocimiento de números de placas requiere seleccionar un modelo de OCR adecuado,
que equilibre precisión, velocidad y facilidad de implementación.
Para ello, se evaluaron cuatro alternativas principales: LPRNet, CLPRNet PaddleOCR y Fast-Plate-OCR.
Cada una de estas arquitecturas presenta ventajas y limitaciones en términos de desempeño, 
compatibilidad con hardware y programas modernos,
facilidad de entrenamiento y grado complejidad en el mantenimiento del proyecto.

Con el fin de fundamentar la selección del modelo final, se elaboró una matriz de decisión (método de Pugh)
considerando los criterios de evaluación mostrados en la tabla~\ref{tab:ocr-criterios-evaluacion}.
A partir de estos criterios, se evaluaron las arquitecturas candidatas (tabla~\ref{tab:comparacion-modelos-ocr}) 
y se calculó una puntuación ponderada según la suma de los productos entre calificación y peso.

De acuerdo con la comparación, Fast-Plate-OCR obtuvo la puntuación más alta,
destacando por su ligereza, velocidad de procesamiento y facilidad de ajuste fino,
además de contar con un proyecto reciente y en constante actualización.
Los modelos que ofrece son rápidos, eficientes y compatibles con las versiones actuales de PyTorch
y GPU NVIDIA, pudiendo entrenarse tanto desde cero como mediante ajuste fino,
lo que simplifica la integración dentro del flujo experimental del sistema.

En contraste, otras arquitecturas presentan limitaciones técnicas o de mantenimiento.
Por ejemplo, LPRNet fue una de las primeras propuestas funcionales para reconocimiento de placas,
pero su desarrollo data de hace aproximadamente seis años,
y su código resulta difícil o incluso imposible de ejecutar en versiones recientes de bibliotecas
\cite{zherzdev2018lprnetlicenseplaterecognition}.
Además, su arquitectura es más rígida y requiere modificaciones sustanciales para adaptar la entrada
y salida a los formatos de datos utilizados en este proyecto.

Por otra parte, CLPRNet propone un enfoque extremo a extremo que unifica la detección 
y el reconocimiento de placas dentro de una sola red~\cite{clprnet-paper}.
Si bien ofrece un alto potencial de precisión, su entrenamiento demanda un etiquetado detallado
que incluye las coordenadas de los vértices de la placa y la clasificación por tipo de matrícula.
Esto implicaría reetiquetar completamente el conjunto de datos disponible y
redefinir la estrategia de generación sintética de imágenes, lo cual excede el alcance de este trabajo.

Finalmente, se consideró PaddleOCR, una herramienta ampliamente usada para OCR
en contextos generales; sin embargo, al igual que LPRNet,
su implementación se encuentra desactualizada y
no puede ejecutarse de forma nativa en entornos recientes de PyTorch y CUDA 
sin reescribir parte del código fuente, lo que comprometería la reproducibilidad y portabilidad del sistema.

En síntesis, tras evaluar las distintas opciones, se decidió emplear Fast-Plate-OCR 
como modelo base para el reconocimiento de caracteres de placas.

Fast plate OCR cuenta con dos modelos pre entrenados. En pruebas de concepto inicial
el modelo más pequeño (XS) resultó en un mejor compromiso entre precisión y velocidad de procesamiento,
por lo que se escoge como modelo base para realizar los experimentos.
El reporte de desempeño brindado por los desarrolladores del modelo base se muestra en la tabla 
\ref{tab:ocr-comparacion-complejidad}, el cual fue evaluado en el hardware NVIDIA RTX 3090 GPU.
La rutina de entrenamiento del modelo se observa en la figura~\ref{fig:entrenamiento-ocr}.

En este caso, se realiza optimización de hiperparámetros para determinar con qué configuración 
se obtienen las mejores métricas de desempeño. Los hiperparámetros incluyen el tipo e
intensidad de aumento de datos, el formato de imágenes de entrada (tamaño y color),
parámetros de optimizador, y parámetros de tamaño de red.
Antes de iniciar el entrenamiento se seleccionan los hiperparámetros y se entrena 
una cantidad determinada de épocas~\ref{fig:entrenamiento-ocr}.

A continuación se listan los principales hiperparámetros considerados en los experimentos:
\begin{enumerate}
	\item \textbf{Optimizador}
	\begin{enumerate}
		\item \textbf{Tasa de aprendizaje:} controla la magnitud del ajuste de pesos en cada iteración.
		Valores demasiado bajos provocan aprendizaje lento, mientras que valores muy altos
		pueden impedir la convergencia o causar inestabilidad numérica.  
		\textit{Rango: } 0.0003 -- 0.001.
		\item \textbf{Decaimiento de pesos:} término de regularización que penaliza pesos grandes
		para prevenir sobreajuste y mejorar la generalización.  
		\textit{Rango: } 0.0002 -- 0.01.
		\item \textbf{Tamaño de lote:} número de muestras procesadas simultáneamente en cada paso de entrenamiento.
		\textit{Valores: } 16, 32, 64.
	\end{enumerate}

	\item \textbf{Imágenes}
	\begin{enumerate}
		\item \textbf{Color:} el uso de canales RGB puede aportar información cromática adicional,
		aunque también puede aumentar la sensibilidad a sombras o variaciones de color.
		\textit{Opciones: } RGB, escala de grises.
		\item \textbf{Resolución:} define la cantidad de información espacial disponible.
		Imágenes de mayor tamaño conservan más detalle pero incrementan el costo computacional.  
		\textit{Altura: } 32, 64, 96 píxeles.  
		\textit{Ancho: } 64, 128, 192 píxeles.
	\end{enumerate}

	\item \textbf{Tamaño de red}
	\begin{enumerate}
		\item \textbf{Capas:} número de bloques del codificador (encoder).  
		\textit{Rango: } 1 -- 4.
		\item \textbf{Cabezas de atención:} número de cabezas empleadas en cada bloque de autoatención multi-cabeza.
		A mayor número, mayor capacidad de modelar dependencias contextuales.  
		\textit{Rango: } 1 -- 2.
		\item \textbf{Dimensión de proyección:} tamaño del espacio de representación interna de cada token visual.
		\textit{Valores: } 32, 64, 96.
		\item \textbf{Función de activación:} define la no linealidad en los bloques intermedios del modelo.  
		\textit{Opciones: } \texttt{ReLU}, \texttt{GeLU}.
		\item \textbf{Caída en atención (Dropout de atención):} porcentaje de conexiones descartadas
		en los pesos de atención, empleado como regularización.  
		\textit{Rango: } 0.05 -- 0.25.
		\item \textbf{Caída en MLP (Dropout en bloque feedforward):} porcentaje de unidades descartadas
		en las capas lineales posteriores al bloque de atención.  
		\textit{Rango: } 0.1 -- 0.25.
	\end{enumerate}
\end{enumerate}

Luego de seleccionar el mejor modelo de detección y el mejor modelo de reconocimiento de placas,
se integran ambos en una única solución. Esta aplicación es capaz de procesar imágenes y video,
ya sea mediante cámara en tiempo real o desde un archivo pregrabado (ver figura~\ref{fig:integracion-app}).

En la imagen~\ref{fig:flujo-app-main} se muestra el bloque principal,
encargado de cargar los modelos e inicializar el modo de operación correspondiente.
Si se selecciona el modo imagen, se carga el archivo desde una ruta dada y se procesa un único cuadro,
como se observa en la figura~\ref{fig:flujo-app-image-mode}.
Por otro lado, si se selecciona el modo video, se procede según se ilustra en la figura~\ref{fig:flujo-app-video-mode}:
se inicializa la cámara o se abre un archivo de video,
y luego se ingresa en un bucle que continúa hasta agotar los cuadros disponibles.
Dentro de este bucle se llama a la rutina encargada del procesamiento de cada cuadro.

En la rutina de procesamiento de cuadros, una vez obtenida la imagen,
se extraen los puntos $(X_{min}, Y_{min})$ y $(X_{max}, Y_{max})$ que corresponden a las cajas delimitadoras.
La región recortada se suministra al modelo de reconocimiento de placas,
obteniéndose el texto reconocido y su nivel de confianza.
Las detecciones con confianza baja (por ejemplo, menor a 0.5) se descartan.
Finalmente, se dibuja la caja delimitadora y el texto asociado sobre la imagen original.
Este proceso se repite hasta que se hayan procesado todos los cuadros disponibles,
tal como se ilustra en la figura~\ref{fig:flujo-app-process-frame}.
